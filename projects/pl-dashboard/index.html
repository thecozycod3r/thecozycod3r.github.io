FinancialP&LDashboard

Built a live financial intelligence layer for DAM's leadership — replacing manual monthly spreadsheets with a real-time BigQuery + Looker Studio dashboard that compressed the reporting cycle and exposed where money was leaking.

The problem

Flying blind, once a month.

When I joined DAM, the only financial visibility leadership had was a manually compiled spreadsheet — updated once a month, emailed around, and already outdated by the time anyone read it. There was no way to tell actuals from projections, no breakdown of where revenue was coming from, and no visibility into which cost lines were eating margin.

Decisions were being made on gut feel. Cost-sink areas were invisible. The leadership team had no live financial pulse.

Monthly reporting cycle

Decisions made on 30-day-old data

No actuals vs. forecast view

Couldn't tell if performance was on track

No cost-sink visibility

Margin erosion went undetected

The build

A live financial command centre.

I built a centralised P&L dashboard in BigQuery (data warehouse + SQL modelling) and Looker Studio (visualisation). Data refreshes automatically on a weekly cadence — no manual input, no email chains.

Features

What the dashboard tracked.

Actuals vs. Forecast

Side-by-side view of actual revenue and expenses against projected figures — updated weekly so leadership always knows if they're on track.

Revenue Stream Breakdown

Revenue split by client, service type (Google Ads, Meta Ads, SEO, CRO), and geography — identifying which streams were growing and which were flat.

Opex Ratio Tracking

Operating expense ratios tracked against revenue benchmarks — flagging when cost lines were growing faster than revenue.

Cost-Sink Identification

Drill-down analysis of individual cost lines identified two categories consuming disproportionate margin — informing a 10%+ cost optimisation initiative.

Tech stack

Built on Google Cloud.

BigQueryLooker StudioSQLGoogle CloudScheduled Queries (auto-refresh)

Data from multiple sources (CRM, invoicing, ad spend) was centralised into BigQuery using SQL data models. Looker Studio connected directly to BigQuery for live visualisations. Scheduled queries handled the weekly refresh automatically — no manual exports or CSV uploads.
